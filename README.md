# AI 담임

## 제품 목표

LLM과 대화하며 여러 과목의 학습 계획을 만들고, 상황에 맞춰 학습 진도를 조율하는 서비스다. **LLM은 사용자 의도를 판단하고 도구를 호출하며, 백엔드 알고리즘은 기한까지의 전체 일정을 계산한다.**

사전 정의된 커리큘럼 선택이나 오늘 수업 목록 변경만으로 목표를 달성한 것으로 보지 않는다.

## 핵심 경험

1. 수강할 강좌, 시작일·마감일, 학습 가능 시간을 바탕으로 다과목의 날짜별 강의 계획을 제안한다.
2. LLM이 “오늘만 시간이 부족해”, “진도를 늦춰줘”, “국어도 추가해줘”의 의도와 적용 범위를 해석한다. 모호한 조건은 질문한다.
3. LLM이 진도 조정 도구로 구체적인 부분 변경을 요청하거나, 전체 재편성 도구로 남은 기간의 균형 배치를 요청한다. 백엔드는 각 도구의 범위와 제약을 검증한다.
4. 변경 내용·이유·기한 영향을 설명하고 사용자 확인 후 저장한다. 재조회·재시작 후에도 같은 계획과 학습 기록을 복구한다.

새 과목은 별도 요청이 없으면 기존 계획에 추가한다. 기존 과목, 완료 기록과 피드백을 보존하며 전체 학습량과 기한을 함께 고려한다.

### 대표 시나리오

DB에 적재된 EBSi 수학·국어·영어 강좌를 대상으로, 실제 강의 목록·길이·순서와 사용자가 지정한 기한·가용 시간에 맞춰 전체 일정을 생성한다. 과목당 30강은 설명용 예시일 뿐 테스트 수량이 아니다. 과거 예시의 복습과 45일씩의 기간 배분은 이번 구현 범위가 아니다.

어느 날 수학001·국어001·영어001이 예정되어 있는데 “오늘은 50분밖에 없어”라고 하면:

- LLM이 오늘 하루의 시간 제한으로 해석해 도구에 전달한다.
- 시간 변경·미완료 이월은 전체 재편성을 우선 사용한다. 부분 조정은 오늘 수학과 내일 국어 교환 같은 세밀한 수정용으로 함께 제공한다. 부분 조정을 먼저 시도할 의무는 없고, 호출하지 않은 전체 재편성이 몰래 실행되지는 않는다.
- 평소 학습 가능 시간은 바꾸지 않는다. 이미 완료한 학습은 다시 배정하거나 취소하지 않는다.
- 강의 자체가 제한 시간보다 길면 임의로 길이를 줄이지 않는다. 기한 준수가 어려우면 미배정 항목·제약·대안을 설명하고 추가 결정을 받는다.

강의 수, 45일 비율, 특정 과목이나 mock 답변은 고정 규칙이 아니다.

### 확정 편성 정책

- 시작일·마감일을 모두 포함하며 시작일을 생략하면 오늘이다.
- 시간은 하루 총한도로 관리한다. “지금부터 50분 더”는 백엔드가 오늘 진행한 시간을 읽어 50분을 더한 총한도로 계산한다.
- 생성·재편성은 하루 상한을 채우는 대신 남은 학습 가능 기간 전체에 분산한다. 실제 잔여 분량·날짜별 여유로 유연한 배정 목표량을 계산하되 시간 상한·강의 순서·이어보기·이월 우선순위를 지킨다. 목표량과 사용자 시간 상한은 별개다.
- 강의는 가능하면 한 날에 끝낸다. 하루 한도보다 길면 같은 강의를 날짜별 이어보기로 배정한다. 70분 강의·하루 50분이면 오늘 50분, 내일 20분이다. 실제로 35분만 수강했다면 남은 35분으로 다시 계산한다.
- 이월 강의는 신규 강의보다 우선하며 오래 밀릴수록 우선순위를 높인다. 재편성해도 최초 이월 기준일과 실제 진도를 보존한다.
- 이어보기 기준은 해당 날짜의 총한도다. 미래에 완강 가능한 날이 있어도 오늘의 이어보기를 막지 않는다. 이월 강의는 실제 사용시간을 뺀 여유에서 우선 이어보고, 신규 강의를 단순 자투리 채우기용으로 나누지는 않는다.
- 균형은 시간·개수의 동일화가 아니라 과목 편중 방지다. 가능한 날에는 여러 과목을 고루 배치하고 한 강의만 가능한 날은 인접 날짜에 과목을 순환한다. 균형을 위해 강의를 일부러 쪼개지 않는다.
- 재등록은 DB 수강 이력을 활용한다. 이어가기·새로 시작의 세부 계약은 추가 논의 대상으로 남긴다. 상세 기준과 검증은 [로드맵](./docs/learning-plan-roadmap.md)을 따른다.

## 역할과 설계 원칙

| 영역 | 책임 |
| --- | --- |
| LLM | 대화 맥락·의도 판단, 필요한 질문, 구조화된 도구 선택·호출, 결과 설명 |
| 백엔드 | 전체 계획 생성·부분 진도 조정·재편성, 시간·순서·선수 관계 검증, 변경 제안·확정 |
| DB | 계획 버전·예정 일정·실행 기록·피드백·변경 근거 보존 |
| 프론트 | 대화, 오늘 수업·전체 계획·변경 비교 표시와 사용자 확인 |

- 학생의 전체 계획에서 다과목을 함께 편성한다. 과목별 상태는 구분하되 서로의 시간을 따로 중복 배정하지 않는다.
- 예정 일정과 실제 완료 기록을 구분한다. 최초 생성과 전체 재편성은 공통 배치 규칙을 사용하고 부분 진도 조정은 별도 변경 범위를 갖는다.
- LLM 없이도 구조화된 HTTP 요청으로 같은 도구의 생성·조정·재편성·확정·조회가 가능해야 한다. 자연어·대화 ID·mock 시나리오를 필수로 요구하지 않는다.
- LLM에 SQL·DB 직접 수정 권한을 주지 않는다. 확인과 서버 검증을 우회할 수 없다.
- 실제 카탈로그와 소요 시간을 사용한다. 없는 강의 생성, 필수 항목의 조용한 삭제, API 실패 시 mock 대체는 하지 않는다.
- 제안 전후의 학습 상태 불변, 확정의 원자성·중복 방지·revision 충돌 처리를 보장한다. 피드백 기록은 별도 계약을 따른다.

## 현재 상태와 진행 순서

R1·R2의 독립 학습 계획 도구와 R3·R4의 [아주LLM 대화·최소 화면](./docs/llm-chat-setup.md)은 합의 범위의 단계별 검증을 수행했다. 실제 모델·브라우저·명시 확인·독립 SQL·서버 재시작 근거와 실행별 한계는 로드맵에서 구분한다. 생성·재편성의 기간 전체 분산 보완은 제작·통합 검증을 마쳤으며 오케스트레이션의 독립 검토 대상으로 전달한다. 기존 학생 계획을 자동 변경하지 않으며, 메인 데모 재설계·요일 반복 조건·완료 후 부분 조정 보완·재등록은 이번 범위에 포함하지 않는다.

1. **생성·저장:** 다과목 날짜별 계획을 LLM 없이 API로 생성·확정하고 DB 저장·복구를 검증한다.
2. **조정·재편성:** 진도 조정과 전체 재편성을 분리하고 학습 진행·조건 변경을 직접 API로 검증한다.
3. **LLM:** 자연어 해석과 도구 호출을 연결해 같은 시나리오를 검증한다.
4. **프론트·통합:** 최소 채팅 화면에서 계획 확인·확정·학습 기록과 실제 연결을 검증한다. 디자인 재설계는 보류하고 API 통신·상태 처리·표시를 분리해 이후 화면 교체가 백엔드 변경을 요구하지 않도록 한다.

복습 콘텐츠·문제 생성·진도/복습 기간 배분은 이번 범위에서 제외한다. 향후 강의와 같은 편성 대상·기한 조건으로 확장할 수 있지만 지금 미리 구현하지 않는다. 세부 편성 정책·도구·DB 계약은 [검토용 로드맵](./docs/learning-plan-roadmap.md)에 따라 확정한다. mock 키워드 확대, 인증·결제·관리자·외부 영상 서비스·RAG는 지금의 우선 작업이 아니다. 인증 없는 상태를 외부 사용자용 서비스로 공개하지 않는다.

## 완료 기준

**DB의 실제 EBSi 다과목 강의 목록 → 전체 일정 생성 → 오늘만 시간 축소 → 필요 시 별도 전체 재편성 → 확인·저장·복구**를 대표 검증으로 삼는다. 강의 수는 실제 조회 결과를 사용하고, 학습 상태 변경은 동일 카탈로그를 준비한 전용 테스트 DB에서 수행한다.

- 날짜별 시간·순서·변경 범위를 지키고 학습 항목이 누락·중복되지 않는다.
- 완료·부분 수강 기록과 이월 기준일, 기존 과목, 다른 학생 데이터가 보존된다.
- 불가능한 요청과 계산 한계를 성공으로 숨기지 않는다.
- 도구 API 결과와 독립 DB 조회가 일치하며 실제 서버 재시작 후 복구된다.
- 백엔드 계산, LLM 해석, 화면 동작을 각각 검증한다. 일부 테스트 통과를 전체 완료로 간주하지 않는다.
- 최종 병합은 사용자 승인 후 진행한다.

## 실행과 문서

기존 실행 명령은 유지한다. PostgreSQL 모드는 실행 중인 DB와 로컬 환경 파일·마이그레이션이 필요하다.

```bash
pnpm dev                 # 프론트 + PostgreSQL 백엔드
pnpm dev:front           # 프론트
pnpm dev:api             # PostgreSQL 백엔드
pnpm dev:api-postgresql  # 위 명령의 별칭
pnpm dev:api-memory      # 명시적 메모리 모드
```
