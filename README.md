# README.md

## AI 담임 서비스 데모

---

## 1. 프로젝트 소개

**AI 담임 서비스 데모**는 기존 인강 서비스처럼 학생이 직접 강의 목록을 보고 수동적으로 학습할 강의를 고르는 방식이 아니라, AI 담임이 오늘의 수업을 먼저 편성하고 학생의 상태에 따라 진도와 보강 계획을 조율하는 경험을 검증하기 위한 프로젝트입니다.

이 프로젝트의 장기 목표는 수능 인강에 한정되지 않고, 코딩 교육, 온라인 대학 강의, 자격증, 직무교육 등 다양한 온라인 학습 영역에 적용 가능한 AI 학습관리 OS로 확장하는 것입니다.

하지만 현재 프로젝트의 **초기 목표는 데모 제작**입니다.

이번 데모에서는 전체 서비스를 완성하지 않고, 사전 정의된 커리큘럼을 기반으로 AI 담임이 진도를 조율하는 핵심 경험만 구현합니다.

---

## 2. 데모 목표

이번 데모의 목표는 다음 기능을 검증하는 것입니다.

> 사전 정의된 커리큘럼을 선택하면, AI 담임이 오늘의 수업을 편성하고, 학생의 요구사항과 학습 결과에 따라 다음 수업과 보강 계획을 조율한다.

즉, 이 데모는 “AI가 커리큘럼을 새로 생성하는 서비스”를 검증하는 것이 아닙니다.

데모의 핵심은 **진도 조율 서비스**입니다.

---

## 3. 핵심 기능

### AI 적응형 진도 운영 엔진

이 프로젝트의 핵심 기능은 다음과 같습니다.

> 사전 정의된 커리큘럼을 기반으로 AI 담임이 오늘의 수업을 편성하고, 학생의 진도·이해도·집중도·요구사항을 반영해 다음 수업과 보강·복구 계획을 조율하는 기능.

핵심 흐름은 다음과 같습니다.

```text
커리큘럼 선택
→ 오늘 수업 제안
→ 학생 요구사항 반영
→ 수업 진행
→ 강의별 간단 체크
→ AI 담임의 내부 다음 수업 조율
→ 오늘의 학습 진행 보고
→ 다음 추천 강의 이어 보기
```

## 4. 데모 범위

### 학습 도메인

```text
과목: 수학 I
단원: 로그함수
대상: 수능 수학 학습자
목표: 로그함수 단원 학습 흐름을 AI 담임이 운영하는 경험 검증
```

수1 전체를 구현하지 않습니다.
로그함수 단원 중심으로 데모를 제작합니다.

## 5. 사전 정의 커리큘럼

데모에서는 사용자가 아래 커리큘럼 중 하나를 선택합니다.

### 5.1 안정형 커리큘럼

```text
1. 로그의 뜻
2. 로그 계산
3. 로그함수 그래프
4. 그래프 보강
5. 로그방정식
6. 로그부등식
7. 종합 복습
```

추천 대상:

* 기초가 약한 학생
* 로그함수 그래프가 불안한 학생
* 안정적으로 개념을 완성하고 싶은 학생

---

### 5.2 압축형 커리큘럼

```text
1. 로그 핵심 개념 요약
2. 로그 계산 확인
3. 로그함수 그래프 핵심
4. 로그방정식
5. 로그부등식
6. 확인 문제 중심 복습
```

추천 대상:

* 이미 한 번 배운 학생
* 시간이 부족한 학생
* 빠르게 전체 흐름을 복습하고 싶은 학생

---

### 5.3 문제적용형 커리큘럼

```text
1. 로그 계산 확인
2. 그래프 문제 적용
3. 방정식 문제 적용
4. 부등식 문제 적용
5. 오답 보강
6. 종합 문제
```

추천 대상:

* 개념은 알고 있지만 문제 적용이 약한 학생
* 문제를 보면 막히는 학생
* 오답 중심으로 공부하고 싶은 학생

## 6. 주요 사용자 흐름

### 6.1 커리큘럼 선택

학생이 사전 정의된 커리큘럼 중 하나를 선택합니다.

```text
안정형 / 압축형 / 문제적용형
```

선택된 커리큘럼은 이후 AI 담임의 진도 조율 기준이 됩니다.

---

### 6.2 AI 담임 홈

AI 담임이 오늘의 수업을 제안합니다.

예시:

```text
오늘 목표:
로그함수 그래프의 점근선과 평행이동 정리

예상 시간:
44분

오늘 수업:
1. 점근선 보강 카드 6분
2. 그래프 확인 문제 3개 5분
3. 점근선과 정의역 강의 9분
4. 평행이동 강의 9분
5. 평행이동 예제 2개 5분
6. 로그방정식 개념 미리 보기 10분
```

---

### 6.3 학생 요구사항 반영

학생은 오늘 상태나 요구사항을 입력할 수 있습니다.

예시:

```text
오늘 시간이 20분밖에 없어요.
오늘은 새 강의보다 복습을 하고 싶어요.
로그함수 그래프가 아직 헷갈려요.
```

AI 담임은 이 요구사항에 따라 오늘 수업을 조정합니다.

---

### 6.4 강의별 간단 체크

학생은 강의가 끝날 때마다 이해도와 집중도만 간단히 선택합니다.

```text
이해도: 이해가 어려웠어요 / 대체로 이해했어요 / 잘 이해했어요
집중도: 집중이 어려웠어요 / 보통이었어요 / 집중했어요
```

헷갈린 개념, 확인 문제 결과, 완료 항목을 별도 설문으로 의무 입력받지 않습니다.
낮은 이해도는 해당 강의의 개념 태그와 연결해 AI 담임의 내부 조율 신호로 사용합니다.
특정 개념이 부족하다고 느낀 학생은 채팅으로 직접 알려 줄 수 있습니다.

---

### 6.5 내부 다음 수업 조율과 진행 보고

다음 수업 조율은 학생에게 상세 카드로 노출하지 않는 AI 담임의 내부 도구입니다.
강의별 간단 체크를 받으면 규칙 기반 엔진이 보강, 수업량, 진도 속도를 내부적으로 다시 계산합니다.

학생에게는 다음 정보만 담은 읽기 전용 `오늘의 학습 진행` 보고 카드를 제공합니다.

```text
완료한 강의
해당 강의의 이해도와 집중도
AI 담임의 짧은 반영 안내
```

## 8. 핵심 모듈 개념

### 8.1 커리큘럼 관리

사전 정의된 커리큘럼을 관리합니다.

역할:

```text
커리큘럼 목록 제공
선택된 커리큘럼 저장
현재 단계 조회
다음 단계 조회
```

---

### 8.2 진도 운영

데모의 핵심 기능입니다.

역할:

```text
오늘 수업 생성
학생 요구사항 반영
진도 밀림 반영
보강 삽입
다음 수업 조율
복구 플랜 생성
```

---

### 8.3 학습 결과 분석

강의 종료 직후의 간단 체크를 분석합니다.

역할:

```text
강의별 이해도와 집중도 기록
낮은 이해도의 강의 개념 태그를 보강 신호로 반영
집중도가 낮을 때 다음 수업량 조정
보강 필요 여부 판단
```

---

### 8.4 AI 담임 응답

AI 담임의 자연어 응답을 담당합니다.

현재 채팅 응답은 백엔드의 교체 가능한 mock LLM 서비스가 API를 통해 반환합니다. 실제 LLM 공급자 연결은 같은 API 계약을 유지한 후속 단계에서 진행합니다.

역할:

```text
AI 담임 코멘트 생성
학생 요구사항 해석
조율 이유 설명
학생 친화적 피드백 생성
```

## 9. AI 사용 원칙

초기 데모에서는 LLM에 모든 판단을 맡기지 않습니다.

### 규칙 기반으로 처리할 것

```text
오늘 수업 구성
이해도에 따른 보강 삽입
집중도에 따른 수업량 축소
진도 밀림에 따른 복구 플랜
다음 수업 재편성
```

### LLM 또는 mock AI가 처리할 것

```text
학생 요구사항 자연어 해석
AI 담임 코멘트 생성
조율 이유 설명
개념 설명 보조
피드백 문장 생성
```

즉, AI 담임은 단순 챗봇이 아니라, 진도 운영 엔진을 자연어로 설명하고 학생 요구사항을 반영하는 인터페이스입니다.

## 11. 데모 구현 이력

```text
커리큘럼 선택
AI 담임 홈
오늘 수업 세션
강의별 간단 체크
오늘의 학습 진행 보고

```

---

### Step 2. mock data 연결

```text
학생 상태
커리큘럼
강의/보강 카드
개념별 이해도
```

---

### Step 3. 오늘 수업 생성 로직 구현

```text
선택된 커리큘럼과 학생 상태를 기반으로 오늘 수업 생성
```

---

### Step 4. 강의별 간단 체크 반영

```text
강의 종료 직후 이해도·집중도만 기록하고, 강의 개념 태그와 함께 상태 업데이트
```

---

### Step 5. 다음 수업 조율

```text
학습 결과에 따라 보강 삽입, 진도 연기, 수업량 조정
```

---

### Step 6. 학생 요구사항 반영

```text
오늘 시간이 부족함
복습 위주 희망
특정 개념이 헷갈림
새 강의 축소 요청
```

---

### Step 7. AI 담임 코멘트 개선

```text
프론트 mock 응답 흐름 구현 완료
백엔드 mock LLM 어댑터 연결 완료
```

### 현재 서비스 전환 우선순위

```text
1. 프론트엔드와 백엔드 Mock API 분리 및 연결: 완료
2. 커리큘럼·오늘 수업·강의별 체크·조율 제안 백엔드 이전: 완료
3. PostgreSQL 저장소·학생별 커리큘럼 버전·원자적 선택: 완료
4. PostgreSQL 현재 버전을 학습 화면 조회 원본으로 전환: 완료
5. 인증 도입: 미진행
6. 실제 LLM 공급자 연결: 미진행
```

## 12. 현재 구현 상태

현재는 Vite + React + TypeScript 기반의 채팅형 데모와 Fastify API 서버를 분리했고, API 서버는 메모리 Mock 모드와 PostgreSQL 모드를 선택해 실행할 수 있습니다.

구현된 내용:

```text

AI 담임 홈 채팅형 인터페이스
```

### 백엔드 API 전환

`apps/api`는 프론트엔드와 분리된 HTTP API 서버입니다. 메모리 모드에서는 기존 Mock 상태를 사용하고, PostgreSQL 모드에서는 강좌·강의, 학생 학습 상태, 피드백, 조율 제안과 학생별 커리큘럼 버전을 영속화합니다. PostgreSQL 모드의 오늘 수업·커리큘럼 맵·학습 진행 조회는 활성 커리큘럼의 현재 버전과 실행 상태를 직접 원본으로 사용합니다.

AI 담임 대화 API는 백엔드의 교체 가능한 mock LLM 서비스가 응답을 생성합니다. 프론트는 계속 상대 경로 `/api`만 사용하며, 모델 공급자·프롬프트·키·도구 정의를 직접 다루지 않습니다. API 경계와 현재 계약은 `docs/backend-api-foundation.md`, mock LLM 교체 원칙은 `docs/teacher-llm-api.md`에서 관리합니다.

학생 요구사항은 대화 API가 조율 제안 카드 데이터로 반환하고, 학생이 확인 API를 호출할 때만 서버 상태에 적용됩니다. 피드백 뒤 다음 수업의 상세 편성 규칙은 다음 백엔드 단계에서 확장합니다.

### 프론트 상태 책임 전환

프론트는 커리큘럼 선택 결과, 오늘 수업, 커리큘럼 맵, 강의별 체크 결과를 API 응답으로만 표시합니다. 오늘 수업 생성, 학생 요청에 따른 조율, 다음 강의 추천을 프론트 규칙으로 다시 계산하지 않습니다.

요청·피드백 API 호출에 실패하면 마지막으로 받은 서버 화면을 유지하고 오류와 재시도 안내만 표시합니다. 프론트 mock 계산으로 대체하지 않습니다.

API의 책임과 초기 엔드포인트는 `docs/backend-api-foundation.md`에서 관리합니다.

도메인, 포트 번호, 외부 API 주소, API 키는 Git에 커밋하지 않습니다. 로컬 개발 환경별 기록은 추적 제외되는 `docs/secrets/`에서만 관리합니다.

### 데모 상태 저장 방식

현재 데모의 학습 상태는 백엔드 API가 관리합니다. 메모리 모드에서는 API 프로세스에, PostgreSQL 모드에서는 DB에 저장합니다. 브라우저의 `localStorage`에는 화면 전환을 위한 현재 데모 단계만 임시 저장합니다.

저장 대상:

```text
현재 데모 단계
```

선택한 커리큘럼, 학생 요청, 강의별 이해도·집중도 기록과 수업 편성은 새로고침 뒤에도 API에서 다시 조회합니다.

주의사항:

```text
데이터는 현재 브라우저와 현재 주소 기준으로만 저장됩니다.
다른 브라우저나 다른 기기와 공유되지 않습니다.
브라우저 저장소를 삭제하면 사라집니다.
학습 상태는 실행 모드에 따라 서버 메모리 또는 로컬 PostgreSQL에 저장됩니다.
API 키, 토큰, 개인정보, 민감한 학습 기록은 localStorage에 저장하지 않습니다.
실제 서비스 단계에서는 인증과 사용자별 접근 제어를 추가해야 합니다.
```

커리큘럼 관리 기능은 다음 파일을 기준으로 구현합니다.

```text
src/features/curriculum/curriculum.types.ts
src/features/curriculum/curriculum.data.ts
src/features/curriculum/curriculum.service.ts
```

오늘 수업 생성 기능은 다음 파일을 기준으로 구현합니다.

```text
src/features/progress-orchestrator/progress.types.ts
src/features/progress-orchestrator/orchestrator.rules.ts
src/features/progress-orchestrator/session-builder.ts
src/features/progress-orchestrator/next-session-builder.ts
src/features/progress-orchestrator/student-request.types.ts
src/features/progress-orchestrator/student-request.rules.ts
```

AI 담임 응답 기능은 다음 파일을 기준으로 구현합니다.

```text
src/features/teacher-response/teacher-response.types.ts
src/features/teacher-response/teacher-response.mock.ts
src/features/teacher-response/teacher-response.service.ts
```

기본 채팅 흐름은 `POST /api/conversations/:conversationId/messages`를 통해 백엔드 mock LLM 서비스의 응답을 받습니다. API를 사용할 수 없으면 마지막 서버 상태를 유지하고 오류 안내를 표시합니다.

AI 담임 응답은 진도 운영 엔진과 학습 결과 분석 결과를 받아 다음 내용을 사용자에게 설명합니다.

```text
오늘 수업을 배정한 기준
학생 요구사항이나 시간 제한 때문에 조정된 내용
강의별 간단 체크 결과에 따라 다음 수업을 내부 조율한 이유
보강·복구가 필요한 경우의 안내 문구
```

추후 실제 LLM 공급자를 연결할 때도 오늘 수업 생성, 보강 삽입, 다음 수업 조율 판단은 규칙 기반 엔진이 담당하고, LLM은 이 결과를 더 자연스럽게 설명하는 역할로 제한합니다.

### 커리큘럼 조율 확장 방향

사용자는 수업 조정 카드에서 옵션을 직접 고르는 대신, 채팅으로 시간 제한·복습 희망·진도 압축·특정 개념 보강 같은 의견을 전달합니다.
AI 담임은 내부 조율 기능을 통해 가장 적절한 편성안을 먼저 제안하고, 사용자의 추가 의견에 따라 다시 조율합니다.

현재 데모에서는 이 경험을 사전 정의된 커리큘럼과 mock 응답으로 보여줍니다.
목표일과 날짜별 가능 시간을 계산하는 전체 커리큘럼 조율 알고리즘은 아직 구현하지 않습니다.
상세 설계는 `docs/curriculum-adjustment-design.md`에서 관리합니다.

강의별 간단 체크 분석 기능은 다음 파일을 기준으로 구현합니다.

```text
src/features/learning-check/learning-check.types.ts
src/features/learning-check/learning-check.rules.ts
src/features/learning-check/learning-check.service.ts
```

## 13. 데모 마감 점검

현재 데모는 실제 LLM 공급자 연결을 제외한 핵심 진도 조율 흐름과 mock LLM 기반 채팅 API를 구현한 상태입니다.

마감 전 확인할 항목:

```text
커리큘럼을 바꾸면 오늘 수업이 다시 생성된다.
학생 요구사항을 선택하면 오늘 수업 시간과 구성이 조정된다.
강의별 이해도·집중도 선택을 보내면 내부 다음 수업 조율 신호와 읽기 전용 진행 보고가 갱신된다.
AI 담임 판단 영역에서 오늘 수업과 다음 수업의 조율 이유가 보인다.
AI 담임 말풍선 안에 현재 상황에 맞는 카드가 첨부되어 표시된다.
첨부 카드는 페이지형 대형 카드가 아니라 채팅 대화에 어울리는 컴팩트 카드로 표시된다.
오늘의 학습 안내 카드는 목표, 시간, 항목을 읽기 전용으로 보여 주며 카드 안에서 직접 조작할 수 없다.
강의 항목의 제목 링크는 같은 사이트 안의 더미 강의 세션으로 이동하며, 돌아오면 AI 담임 대화 상태가 유지된다.
강의별 간단 체크를 전달하면 AI 담임이 0.5초간 응답한 뒤, 영상 재생이 가능한 다음 추천 강의에만 5초 자동 재생 카운트를 채팅으로 안내한다. 보강·문제·확인 항목은 자동 재생하지 않으며 종류에 맞는 시작 버튼을 표시한다. 전용 화면이 아직 없는 경우에는 영상 재생을 시도하지 않고 준비 안내를 표시한다.
아직 완료하지 않은 필수 강의는 내부 다음 수업 조율에서 이월 대상으로 유지한다.
버튼이나 입력을 사용하면 기존 말풍선을 바꾸지 않고 사용자 메시지와 AI 응답이 대화 기록에 누적된다.
AI 응답 전에는 0.5초 동안 준비 중 점 애니메이션이 표시된다.
우측 상단 개발용 단계 이동 컨트롤로 AI 답변에 실릴 카드를 강제로 바꿀 수 있다.
새로고침 후 localStorage에 저장된 데모 상태가 복원된다.
```

보안 및 저장소 확인:

```text
.gitignore가 환경 변수, API 키 문서, 로그, 빌드 산출물, 로컬 데이터 파일, 개별 클레임 문서를 제외한다.
localStorage에는 데모 진행 상태만 저장한다.
API 키, 토큰, 개인정보, 민감한 학습 기록은 저장하지 않는다.
```

현재 의도적으로 하지 않은 일:

```text
실제 LLM 공급자 연결
로그인
결제
실제 영상 스트리밍
관리자 페이지
```

## 14. 실행 방법

의존성을 설치한 뒤 개발 서버를 실행합니다. 기본 명령은 프론트엔드와 PostgreSQL 백엔드를 함께 실행합니다.

```bash
pnpm install
pnpm dev
```

개별 실행 명령은 다음과 같습니다.

```bash
pnpm dev:front
pnpm dev:api
pnpm dev:api-postgresql
pnpm dev:api-memory
```

`pnpm dev`와 `pnpm dev:api`는 Git 제외 `.env.db.local`을 자동으로 읽고 PostgreSQL 모드로 실행합니다. DB 컨테이너·마이그레이션은 자동으로 만들거나 적용하지 않으므로, 실행 전에 `docs/database-operations.md`의 준비 절차를 완료해야 합니다. memory 모드는 `pnpm dev:api-memory`로만 명시적으로 실행합니다.

프론트 개발 서버는 Git 제외 `.env.local`의 `API_PROXY_TARGET`을 읽어 `/api` 요청을 백엔드로 전달합니다. 로컬 환경 값을 변경한 뒤에는 프론트 개발 서버를 다시 시작해야 합니다.

빌드 확인:

```bash
pnpm build
```

백엔드 API 테스트:

```bash
pnpm --filter @ai-homeroom/api test
```

### PostgreSQL 개발 저장소

백엔드는 `PERSISTENCE_MODE=postgres`일 때 PostgreSQL 저장소를 사용합니다. 강좌·강의 카탈로그와 데모 학생 `000`의 후보 커리큘럼 3종을 DB에서 조회하며, 학생별 학습 상태·revision·강의 피드백 이력·오늘 수업 조율 제안은 서버 재시작 뒤에도 복구됩니다.

커리큘럼은 `student_curricula`와 불변 `curriculum_versions`·`curriculum_steps`·`curriculum_items`로 저장합니다. 후보 소개 정보는 `presentation_json`으로 저장하며, 단계·항목의 원본 식별자는 `source_id`로 보존합니다. 구조 변경은 해당 과목의 실행 상태와 같은 트랜잭션으로 저장하고, 강의형 항목은 DB의 실제 `lessons` 행을 반드시 참조합니다. 선택 전 학습 화면 조회는 `409 CURRICULUM_SELECTION_REQUIRED`를 반환합니다. 상태 변경은 과목별 `student_learning_states`의 revision을 한 번만 증가시키며, 조율 제안 확정은 제안 행과 학습 상태 행을 같은 트랜잭션에서 잠가 중복 확정과 오래된 revision을 방지합니다. 기존 규칙 기반 진도 판단과 HTTP API 응답 계약은 유지합니다.

로컬 PostgreSQL 실행, 마이그레이션, seed, 복구와 초기화 절차는 [database-operations.md](./docs/database-operations.md)를 참고합니다.
