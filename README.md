# README.md

## AI 담임 서비스 데모

---

## 1. 프로젝트 소개

**AI 담임 서비스 데모**는 기존 인강 서비스처럼 학생이 직접 강의 목록을 보고 수동적으로 학습할 강의를 고르는 방식이 아니라, AI 담임이 오늘의 수업을 먼저 편성하고 학생의 상태에 따라 진도와 보강 계획을 조율하는 경험을 검증하기 위한 프로젝트입니다.

이 프로젝트의 장기 목표는 수능 인강에 한정되지 않고, 코딩 교육, 온라인 대학 강의, 자격증, 직무교육 등 다양한 온라인 학습 영역에 적용 가능한 AI 학습관리 OS로 확장하는 것입니다.

하지만 현재 프로젝트의 **초기 목표는 데모 제작**입니다.

이번 데모에서는 전체 서비스를 완성하지 않고, 사전 정의된 커리큘럼을 기반으로 AI 담임이 진도를 조율하는 핵심 경험만 구현합니다.

---

## 2. 데모 목표

이번 데모의 목표는 다음 기능을 검증하는 것입니다.

> 사전 정의된 커리큘럼을 선택하면, AI 담임이 오늘의 수업을 편성하고, 학생의 요구사항과 학습 결과에 따라 다음 수업과 보강 계획을 조율한다.

즉, 이 데모는 “AI가 커리큘럼을 새로 생성하는 서비스”를 검증하는 것이 아닙니다.

데모의 핵심은 **진도 조율 서비스**입니다.

---

## 3. 핵심 기능

### AI 적응형 진도 운영 엔진

이 프로젝트의 핵심 기능은 다음과 같습니다.

> 사전 정의된 커리큘럼을 기반으로 AI 담임이 오늘의 수업을 편성하고, 학생의 진도·이해도·집중도·요구사항을 반영해 다음 수업과 보강·복구 계획을 조율하는 기능.

핵심 흐름은 다음과 같습니다.

```text
커리큘럼 선택
→ 오늘 수업 제안
→ 학생 요구사항 반영
→ 수업 진행
→ 학습 후 체크
→ 다음 수업 조율
```

## 4. 데모 범위

### 학습 도메인

```text
과목: 수학 I
단원: 로그함수
대상: 수능 수학 학습자
목표: 로그함수 단원 학습 흐름을 AI 담임이 운영하는 경험 검증
```

수1 전체를 구현하지 않습니다.
로그함수 단원 중심으로 데모를 제작합니다.

## 5. 사전 정의 커리큘럼

데모에서는 사용자가 아래 커리큘럼 중 하나를 선택합니다.

### 5.1 안정형 커리큘럼

```text
1. 로그의 뜻
2. 로그 계산
3. 로그함수 그래프
4. 그래프 보강
5. 로그방정식
6. 로그부등식
7. 종합 복습
```

추천 대상:

* 기초가 약한 학생
* 로그함수 그래프가 불안한 학생
* 안정적으로 개념을 완성하고 싶은 학생

---

### 5.2 압축형 커리큘럼

```text
1. 로그 핵심 개념 요약
2. 로그 계산 확인
3. 로그함수 그래프 핵심
4. 로그방정식
5. 로그부등식
6. 확인 문제 중심 복습
```

추천 대상:

* 이미 한 번 배운 학생
* 시간이 부족한 학생
* 빠르게 전체 흐름을 복습하고 싶은 학생

---

### 5.3 문제적용형 커리큘럼

```text
1. 로그 계산 확인
2. 그래프 문제 적용
3. 방정식 문제 적용
4. 부등식 문제 적용
5. 오답 보강
6. 종합 문제
```

추천 대상:

* 개념은 알고 있지만 문제 적용이 약한 학생
* 문제를 보면 막히는 학생
* 오답 중심으로 공부하고 싶은 학생

## 6. 주요 사용자 흐름

### 6.1 커리큘럼 선택

학생이 사전 정의된 커리큘럼 중 하나를 선택합니다.

```text
안정형 / 압축형 / 문제적용형
```

선택된 커리큘럼은 이후 AI 담임의 진도 조율 기준이 됩니다.

---

### 6.2 AI 담임 홈

AI 담임이 오늘의 수업을 제안합니다.

예시:

```text
오늘 목표:
로그함수 그래프의 점근선과 평행이동 정리

예상 시간:
42분

오늘 수업:
1. 점근선 보강 카드 8분
2. 평행이동 예제 2개
3. 로그함수 그래프 확인 문제 3개
4. 로그방정식 개념 강의 20분
```

---

### 6.3 학생 요구사항 반영

학생은 오늘 상태나 요구사항을 입력할 수 있습니다.

예시:

```text
오늘 시간이 20분밖에 없어요.
오늘은 새 강의보다 복습을 하고 싶어요.
로그함수 그래프가 아직 헷갈려요.
```

AI 담임은 이 요구사항에 따라 오늘 수업을 조정합니다.

---

### 6.4 학습 후 체크

수업 후 학생은 다음 정보를 입력합니다.

```text
완료 여부
이해도
집중도
헷갈린 개념
확인 문제 결과
```

---

### 6.5 다음 수업 조율

AI 담임은 학습 후 체크 결과를 바탕으로 다음 수업을 조정합니다.

예시:

```text
기존 내일 수업:
로그방정식 개념 강의 35분

조정 후 내일 수업:
1. 평행이동 보강 8분
2. 그래프 확인 문제 2개
3. 로그방정식 개념 강의 25분
```

## 9. AI 사용 원칙

초기 데모에서는 LLM에 모든 판단을 맡기지 않습니다.

### 규칙 기반으로 처리할 것

```text
오늘 수업 구성
이해도에 따른 보강 삽입
집중도에 따른 수업량 축소
진도 밀림에 따른 복구 플랜
다음 수업 재편성
```

### LLM 또는 mock AI가 처리할 것

```text
학생 요구사항 자연어 해석
AI 담임 코멘트 생성
조율 이유 설명

피드백 문장 생성
```

즉, AI 담임은 단순 챗봇이 아니라, 진도 운영 엔진을 자연어로 설명하고 학생 요구사항을 반영하는 인터페이스입니다.

## 12. 현재 구현 상태

현재는 Vite + React + TypeScript 기반의 프론트엔드 프로젝트 골격을 추가하고, 첫 정적 화면으로 AI 담임 홈을 구성했습니다.

구현된 내용:

```text
Vite 실행 설정
React 앱 진입점
AI 담임 홈 정적 화면
AI 담임 홈 채팅형 인터페이스
오늘 수업 세션 mock data
커리큘럼 맵 mock data
커리큘럼 타입 정의
안정형/압축형/문제적용형 커리큘럼 mock data
커리큘럼 목록/현재 단계/다음 단계 조회 서비스
선택된 커리큘럼과 학생 상태 기반 오늘 수업 생성 로직
취약 개념 보강 우선 배치 규칙
수업 시간 제한에 따른 선택 항목 이동 규칙
AI 담임 응답 mock 모듈
AI 담임 판단 근거 목록 표시
오늘 수업·다음 수업 조율 이유 코멘트 개선
학습 후 체크 결과 분석 로직
학습 결과 기반 다음 수업 조율 엔진
커리큘럼 선택 상호작용
학생 요구사항 선택 UI
학생 요구사항 기반 오늘 수업 조정 로직
학습 후 체크 입력 UI
학습 후 체크 요약 및 다음 수업 조율 결과 UI
localStorage 기반 데모 상태 저장
스텝형 인터랙션 플로우 UI
우측 상단 개발용 단계 강제 이동 컨트롤
AI 담임 홈 예시 답변 및 텍스트 입력 UI
기본 스타일
```

아직 구현되지 않은 내용:

```text
LLM API 연결
```

### 데모 상태 저장 방식

현재 데모는 서버나 데이터베이스를 사용하지 않고, 브라우저의 `localStorage`에 일부 상태를 임시 저장합니다.

저장 대상:

```text
선택한 커리큘럼
선택한 학생 요구사항
학습 후 체크 입력값
현재 데모 단계
```

이 저장 방식은 **데모 화면을 새로고침해도 흐름을 이어 보기 위한 임시 저장소**입니다.

주의사항:

```text
데이터는 현재 브라우저와 현재 주소 기준으로만 저장됩니다.
다른 브라우저나 다른 기기와 공유되지 않습니다.
브라우저 저장소를 삭제하면 사라집니다.
서버, GitHub, 외부 데이터베이스에는 저장되지 않습니다.
API 키, 토큰, 개인정보, 민감한 학습 기록은 localStorage에 저장하지 않습니다.
실제 서비스 단계에서는 서버 저장소나 데이터베이스로 대체해야 합니다.
```

커리큘럼 관리 기능은 다음 파일을 기준으로 구현합니다.

```text
src/features/curriculum/curriculum.types.ts
src/features/curriculum/curriculum.data.ts
src/features/curriculum/curriculum.service.ts
```

오늘 수업 생성 기능은 다음 파일을 기준으로 구현합니다.

```text
src/features/progress-orchestrator/progress.types.ts
src/features/progress-orchestrator/orchestrator.rules.ts
src/features/progress-orchestrator/session-builder.ts
src/features/progress-orchestrator/next-session-builder.ts
src/features/progress-orchestrator/student-request.types.ts
src/features/progress-orchestrator/student-request.rules.ts
```

AI 담임 응답 기능은 다음 파일을 기준으로 구현합니다.

```text
src/features/teacher-response/teacher-response.types.ts
src/features/teacher-response/teacher-response.mock.ts
src/features/teacher-response/teacher-response.service.ts
```

현재 AI 담임 응답은 LLM API가 아니라 mock 응답 모듈에서 생성합니다.
진도 운영 엔진과 학습 결과 분석 결과를 받아 다음 내용을 사용자에게 설명합니다.

```text
오늘 수업을 배정한 기준
학생 요구사항이나 시간 제한 때문에 조정된 내용
학습 후 체크 결과에 따라 다음 수업이 바뀐 이유
보강·복구가 필요한 경우의 안내 문구
```

추후 LLM API를 연결할 때도 오늘 수업 생성, 보강 삽입, 다음 수업 조율 판단은 규칙 기반 엔진이 담당하고, LLM은 이 결과를 더 자연스럽게 설명하는 역할로 제한합니다.

학습 후 체크 분석 기능은 다음 파일을 기준으로 구현합니다.

```text
src/features/learning-check/learning-check.types.ts
src/features/learning-check/learning-check.rules.ts
src/features/learning-check/learning-check.service.ts
```

## 13. 데모 마감 점검

현재 데모는 LLM API 연결을 제외한 핵심 진도 조율 흐름을 구현한 상태입니다.

마감 전 확인할 항목:

```text
커리큘럼을 바꾸면 오늘 수업이 다시 생성된다.
학생 요구사항을 선택하면 오늘 수업 시간과 구성이 조정된다.
학습 후 체크 입력값을 바꾸면 다음 수업 조율 결과가 바뀐다.
AI 담임 판단 영역에서 오늘 수업과 다음 수업의 조율 이유가 보인다.
현재 상황에 맞는 카드 하나만 중앙에 표시된다.
우측 상단 개발용 단계 이동 컨트롤로 모든 카드를 강제로 이동할 수 있다.
새로고침 후 localStorage에 저장된 데모 상태가 복원된다.
```

보안 및 저장소 확인:

```text
.gitignore가 환경 변수, API 키 문서, 로그, 빌드 산출물, 로컬 데이터 파일을 제외한다.
localStorage에는 데모 진행 상태만 저장한다.
API 키, 토큰, 개인정보, 민감한 학습 기록은 저장하지 않는다.
```

현재 의도적으로 하지 않은 일:

```text
LLM API 연결
로그인
결제
DB 저장
실제 영상 스트리밍
관리자 페이지
```

## 15. 데모 성공 기준

다음 조건을 만족하면 데모 목적을 달성한 것으로 봅니다.

1. 사용자가 커리큘럼을 선택할 수 있다.
2. 선택된 커리큘럼에 따라 오늘 수업이 자동 생성된다.
3. 오늘 수업이 강의 목록이 아니라 수업 세션처럼 보인다.
4. 학생 요구사항에 따라 오늘 수업이 조정된다.
5. 학습 후 체크 결과가 다음 수업에 반영된다.
6. 조율 결과가 명확하게 표시된다.
7. AI 담임이 “왜 이렇게 조정했는지” 설명한다.
8. 커리큘럼 맵에서 진도와 취약 개념 상태가 보인다.
