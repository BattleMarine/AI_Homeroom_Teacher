# 백엔드 개발 브리프

## 문서 목적

이 문서는 프론트엔드와 분리된 백엔드 개발 세션이 프로젝트의 목적, 현재 상태, 책임 경계, 다음 구현 순서를 빠르게 이해하도록 돕습니다.

백엔드는 단순히 AI 모델을 호출하는 중계 서버가 아닙니다. **AI 적응형 진도 운영 엔진**의 규칙 기반 판단을 실행하고, 그 결과를 AI 담임이 학생에게 설명할 수 있는 형태로 제공하는 서비스 계층입니다.

## 제품 목표

> 사전 정의된 커리큘럼을 기반으로 AI 담임이 오늘 수업을 편성하고, 학생의 요구사항과 강의별 학습 결과에 따라 다음 수업과 보강 계획을 조율한다.

핵심 원칙은 다음과 같습니다.

```text
진도 편성과 조율 판단은 규칙 기반 엔진이 담당한다.
LLM은 학생의 자연어 요구를 해석하고, 엔진의 판단 결과를 자연스럽게 설명한다.
LLM이 커리큘럼 상태를 임의로 바꾸거나 판단을 독점하지 않는다.
```

## 현재 구현 상태

현재 저장소에는 `apps/api`의 Fastify 기반 API 서버가 있습니다. `PERSISTENCE_MODE=memory`이면 메모리 저장소와 파일 카탈로그를 사용하고, `postgres`이면 `DATABASE_URL`로 PostgreSQL의 강좌·학생 진도·학생별 커리큘럼 버전 저장소를 사용합니다. 실제 LLM은 아직 연결하지 않았습니다.

PostgreSQL에는 학생·강좌·강의·학습 상태·피드백·조율 제안과 학생별 커리큘럼·불변 버전·단계·항목이 구현되어 있습니다. 학생·과목별 활성 커리큘럼 선택, `revision` 증가, 화면 메타데이터와 `sourceId`를 포함한 현재 버전 읽기 모델도 지원합니다. 다음 과제는 이 읽기 모델을 오늘 수업·커리큘럼 맵·강의 상세 API의 단일 원천으로 연결하는 것입니다.

현재 API는 다음 책임을 검증합니다.

| 메서드 | 경로 | 현재 책임 |
| --- | --- | --- |
| `GET` | `/api/health` | 서버 상태를 반환 |
| `GET` | `/api/today-session` | 현재 학습 상태를 기준으로 오늘 수업을 반환 |
| `GET` | `/api/curriculum-map` | 현재 학습 상태를 기준으로 커리큘럼 맵을 반환 |
| `POST` | `/api/conversations/:conversationId/messages` | 학생 메시지에 대한 mock AI 담임 응답을 반환 |
| `POST` | `/api/lesson-feedback` | 강의별 이해도·집중도 기록 결과를 반환 |

AI 담임 대화 API는 `apps/api/src/teacher-llm/`의 교체 가능한 mock LLM 서비스로 동작합니다. 실제 LLM 공급자 연결 전까지는 같은 응답 계약을 유지하며, 상세 설계는 `docs/teacher-llm-api.md`에서 관리합니다.

실제 코드와 초기 API 계약은 [backend-api-foundation.md](./backend-api-foundation.md)를 기준으로 확인합니다.

## 책임 경계

```text
프론트엔드
  채팅 UI, 강의 화면, 입력 검증 보조, API 응답 렌더링

백엔드 API
  요청 검증, 인증 이후 사용자 식별, 진도 엔진 호출,
  데이터 저장, LLM 도구 호출 오케스트레이션, 응답 계약 유지

규칙 기반 진도 엔진
  오늘 수업 편성, 시간 제한 반영, 보강 삽입,
  진도 압축·완화, 다음 수업 조율, 복구 계획 계산

LLM 어댑터
  자연어 의도 해석, 도구 호출 요청, 학생 친화적 설명 생성
```

프론트엔드는 개발 환경과 배포 환경 모두에서 상대 경로 `/api`만 호출합니다. API 서버 주소와 외부 서비스 주소는 프론트 코드나 추적되는 문서에 넣지 않습니다.

## 목표 도메인

백엔드는 아래 데이터를 중심으로 확장합니다.

| 도메인 | 핵심 정보 | 백엔드 역할 |
| --- | --- | --- |
| 커리큘럼 | 단계, 순서, 강의, 목표일 | 기준 학습 계획 조회 |
| 학생 상태 | 현재 단계, 가능 시간, 선호, 취약 개념 | 편성 입력값 제공 |
| 오늘 수업 | 목표, 항목, 예상 시간, 필수 여부 | 오늘 학습 세션 생성·저장 |
| 학습 기록 | 강의 완료, 이해도, 집중도, 시각 | 다음 조율의 근거 저장 |
| 조율 제안 | 변경 이유, 변경 항목, 학생 확인 상태 | AI 담임 대화의 구조화된 결과 |
| 대화 | 사용자 발화, AI 담임 응답, 도구 호출 결과 | 맥락 유지와 감사 가능성 확보 |

세부 개념은 [domain-model.md](./domain-model.md), 조율 기준은 [orchestration-rules.md](./orchestration-rules.md), 복합 조율 방향은 [curriculum-adjustment-design.md](./curriculum-adjustment-design.md)을 함께 참고합니다.

## 개발 단계

### 1. API 계약을 프론트엔드에 연결

API 응답을 프론트엔드의 오늘 수업 안내, 커리큘럼 맵, 채팅 메시지, 강의별 체크 화면에 연결한 단계이며 현재 완료되었습니다.

완료 기준:

```text
프론트엔드가 직접 mock 파일을 읽지 않고 API 클라이언트로 필요한 데이터를 받는다.
API 오류와 로딩 상태가 화면에서 구분된다.
기존 데모 흐름이 깨지지 않는다.
```

### 2. 규칙 기반 진도 엔진을 백엔드로 이동

프론트엔드에 있는 오늘 수업 생성·학습 후 조율 로직을 API 내부의 도메인 모듈로 옮깁니다. 화면은 판단하지 않고, 입력과 결과를 API로 주고받습니다.

완료 기준:

```text
학생 상태와 커리큘럼을 입력하면 오늘 수업 편성 결과가 재현 가능하게 반환된다.
강의별 체크 결과가 다음 수업 조율에 반영된다.
조율 결과에는 학생에게 설명할 수 있는 이유 코드와 요약이 포함된다.
```

### 3. 영속 저장소 도입

PostgreSQL과 Drizzle 기반 스키마·마이그레이션·seed·저장소가 구현되었습니다. 강좌 카탈로그, 학생별 진도 상태, 피드백, 조율 제안과 학생별 커리큘럼 버전을 저장하며, 로컬 실행과 복구 절차는 [database-operations.md](./database-operations.md)를 따릅니다.

프론트 `localStorage`에는 데모 화면 단계만 남아 있습니다. 인증은 아직 도입하지 않았고, 현재의 임시 `studentId`는 인증 도입 시 서버가 식별한 사용자로 교체해야 합니다.

### 4. AI 담임 LLM 도구 호출 연결

LLM은 백엔드에서만 호출합니다. 프론트엔드는 모델명, API 키, 도구 정의, 원문 응답을 알 필요가 없습니다.

초기 도구 후보:

```text
get_student_context
get_today_session
adjust_curriculum
record_lesson_feedback
get_curriculum_map
```

도구 호출 흐름:

```text
학생 메시지 수신
  -> 의도 해석
  -> 필요한 서버 도구 호출
  -> 규칙 기반 엔진으로 조율 결과 계산
  -> 구조화된 결과 검증
  -> 학생용 AI 담임 응답 생성
  -> 대화와 조율 결과 저장
```

학생의 동의가 필요한 변경은 즉시 확정하지 않습니다. AI 담임이 제안안을 먼저 설명하고, 학생의 추가 의견이나 동의를 받은 뒤 적용합니다.

## API 설계 원칙

```text
API는 화면 컴포넌트가 아니라 도메인 행동을 기준으로 설계한다.
요청 본문·경로 변수·응답 타입을 검증한다.
저장소 모드는 서버 설정과 시작 로그에서 명확히 확인할 수 있게 한다.
수업 조율 결과에는 변경 내용뿐 아니라 변경 이유와 확인 필요 여부를 포함한다.
호환성을 깨는 필드 변경은 프론트엔드 세션과 합의한 뒤 문서와 클라이언트를 함께 수정한다.
```

예를 들어 학생이 "오늘 시간이 부족한데 복습도 하고 싶어요"라고 말하면, 백엔드는 이를 단일 문자열 응답으로 끝내지 않습니다. 시간 제한과 복습 우선이라는 조합 조건을 진도 엔진 입력으로 전달하고, 가능한 편성안과 그 근거를 구조화된 데이터로 반환해야 합니다.

## 품질 기준

```text
Fastify 앱 생성 함수와 서버 실행 코드를 분리한다.
핸들러는 입력 검증, 도메인 서비스 호출, 응답 변환만 담당한다.
도메인 규칙은 순수 함수에 가깝게 작성해 단위 테스트가 가능하도록 한다.
HTTP 검증은 서버를 실제 포트에 띄우지 않아도 확인할 수 있게 앱 주입 테스트를 우선한다.
학생 메시지, 토큰, API 키, 개인 학습 데이터가 로그에 그대로 남지 않게 한다.
```

## 환경·보안 원칙

도메인, 포트, 외부 API 주소, 키, 토큰, 로컬 연결 문자열은 Git 추적 대상이 아닌 `docs/secrets/`에서만 관리합니다.

```text
추적되는 코드와 문서에는 실제 비밀값을 작성하지 않는다.
환경 변수의 이름과 필요한 이유만 문서화한다.
키가 없는 mock 단계에서도 실제 키 형식의 예시를 넣지 않는다.
로그와 임시 산출물은 .gitignore 대상인지 확인한다.
```

## 백엔드 세션의 작업 규칙

1. 작업 전에 `README.md`, `AGENTS.md`, 이 문서, `backend-api-foundation.md`를 읽습니다.
2. API 계약 또는 데이터 개념을 바꾸면 관련 문서를 같은 작업에서 업데이트합니다.
3. 프론트엔드가 소비하는 응답을 바꿀 때는 `src/api/teacher-api.ts`와 프론트엔드 세션에 변경점을 전달합니다.
4. mock 단계에서는 로그인, 결제, 관리자, RAG, 실제 스트리밍을 구현하지 않습니다.
5. LLM 연동 전에 규칙 기반 조율 결과와 도구 입출력 계약을 먼저 고정합니다.
6. 커밋 메시지는 `AGENTS.md`의 한국어 형식을 따릅니다.

## 다음 백엔드 작업 제안

가장 먼저 할 일은 PostgreSQL의 활성 커리큘럼 읽기 모델을 화면 API의 단일 원천으로 연결하는 것입니다.

```text
1. 읽기 모델을 오늘 수업, 커리큘럼 맵, 강의 상세 조회에 공급한다.
2. DB 레코드가 없을 때 파일·메모리 데이터로 조용히 우회하지 않도록 오류 계약을 고정한다.
3. 선택 직후와 서버 재시작 뒤에도 같은 버전과 `sourceId`가 반환되는 통합 테스트를 추가한다.
4. 이후 인증과 실제 LLM 연결을 진행한다.
```

이 작업이 끝나면 화면 조회와 진도 변경이 같은 PostgreSQL 커리큘럼 버전을 기준으로 동작합니다.
