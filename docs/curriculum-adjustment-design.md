# 커리큘럼 조율 설계 방향

## 목적

AI 담임은 학생에게 여러 조율 옵션을 나열해 선택하게 하는 도구가 아니라,
학생의 자연어 요청과 학습 상태를 바탕으로 가장 적절한 수업 편성안을 먼저 제안하는 역할을 합니다.

이 문서는 장기적으로 구현할 커리큘럼 조율 방식과, 현재 데모에서 보여줄 범위를 구분하기 위해 작성합니다.

## 핵심 경험

학생은 커리큘럼 설정 화면이나 별도의 수업 조정 카드를 직접 다루지 않습니다.
대화 안에서 자신의 상황과 의견을 말하면, AI 담임이 내부 조율 도구를 사용해 수업 편성안을 제안합니다.

```text
학생: 오늘은 시간이 부족한데 복습 위주로 하고 싶어요.

AI 담임 내부:
시간 제한과 복습 선호를 함께 반영해 오늘 수업과 이후 진도를 계산한다.

AI 담임:
오늘은 20분 복습과 확인 문제만 진행하고,
새 강의는 내일 수업으로 옮기겠습니다.
이후 선택 연습을 종합 복습으로 통합하면 목표일까지의 흐름은 유지할 수 있어요.
이 편성으로 진행할까요?
```

학생은 `좋아요`, `내일도 시간이 부족해요`, `그래도 새 진도는 조금 듣고 싶어요`처럼 의견을 보냅니다.
AI 담임은 의견을 다시 반영해 제안안을 수정하거나 확정합니다.

## 사용자에게 보이는 것과 내부 도구의 분리

### 사용자에게 보이는 것

```text
AI 담임의 수업 편성 설명
조정된 오늘 수업의 목표, 시간, 항목 요약이 담긴 AI 담임 메시지
조정 이유와 목표일 영향
편성안에 대한 확인 요청
사용자의 자연어 답변과 예시 답변
```

### 사용자에게 보이지 않는 것

```text
요구사항 반영 도구 호출
시간 제한, 복습 선호, 진도 압축 등의 구조화된 조건
수업 항목 재배치 과정
보강 삽입, 진도 연기, 선택 항목 통합 판단
편성안 점수 계산과 우선순위 충돌 처리
```

따라서 `요구사항 반영`은 AI 담임이 답변에 첨부하는 공개 카드가 아니라,
`Adaptive Progress Orchestrator`가 내부적으로 호출하는 조율 기능입니다.

## 조율 가능한 축

커리큘럼 조율은 하나의 요청만 처리하지 않고, 여러 조건을 함께 반영할 수 있어야 합니다.

| 조율 축 | 학생 요청 예시 | 내부 조정 |
| --- | --- | --- |
| 오늘 시간 제한 | 오늘은 20분만 가능해요 | 오늘 수업의 시간 상한을 적용하고 낮은 우선순위 항목을 이동합니다. |
| 전체 진도 압축 | 시험 전까지 끝내고 싶어요 | 선택 연습을 통합하고 핵심 개념 중심으로 이후 수업을 재배치합니다. |
| 전체 진도 완화 | 이번 주는 조금 느슨하게 하고 싶어요 | 긴 수업을 나누고 하루 수업량을 줄입니다. |
| 복습 우선 | 새 진도보다 복습하고 싶어요 | 취약 개념 보강과 확인 문제 비중을 높이고 새 진도를 뒤로 옮깁니다. |
| 문제 풀이 우선 | 개념보다 문제를 풀고 싶어요 | 개념 강의를 핵심 요약으로 조정하고 적용 문제를 앞에 둡니다. |
| 특정 개념 보강 | 평행이동이 헷갈려요 | 해당 개념의 보강과 확인 문제를 앞쪽에 배치합니다. |
| 미완료 복구 | 지난 수업을 못 했어요 | 미완료 필수 항목을 복구 계획에 넣고 이후 진도를 재배치합니다. |

예를 들어 `오늘 시간 제한 + 복습 우선 + 목표일 유지`는 서로 독립적인 조건이 아니라,
하나의 복합 조율 요청으로 함께 계산합니다.

## 조율 원칙

AI 담임은 여러 가능한 계획을 모두 사용자에게 나열하지 않습니다.
현재 학생 상태와 기본 정책을 바탕으로 가장 적절한 편성안 하나를 먼저 제안하고,
학생의 피드백이 있을 때만 다시 조율합니다.

기본 정책은 다음과 같습니다.

```text
필수 개념을 설명 없이 삭제하지 않는다.
시간이 부족하면 선택 연습과 새 진도를 먼저 이동한다.
취약 개념은 가능한 한 짧게라도 보강한다.
미완료 필수 항목은 사라지지 않고 복구 계획으로 이동한다.
목표일 유지가 어려우면 사실을 숨기지 않고 가장 부담이 적은 복구안을 제안한다.
하루 학습량이 과도해지지 않도록 제한한다.
```

여러 조건이 충돌할 때의 기본 우선순위는 다음과 같습니다.

```text
1. 오늘 확정 시간 제한
2. 미완료 필수 항목 복구
3. 취약 개념 보강
4. 목표일과 전체 진도 페이스
5. 복습·문제 풀이 등 학습 선호
6. 선택 연습과 추가 항목
```

목표일과 학습 품질을 동시에 지킬 수 없는 경우에도,
AI 담임은 가장 적절하다고 판단한 안을 먼저 제안하고 그 근거를 설명합니다.
사용자에게 결정 책임을 넘기기보다, 사용자가 수정 의견을 낼 수 있도록 대화를 엽니다.

## 장기 구현 모델

전체 커리큘럼 조율은 일정 최적화 문제로 구현할 수 있습니다.
핵심 판단은 LLM이 아니라 규칙 기반 또는 제약 기반 알고리즘이 담당합니다.

```text
입력: 목표일, 남은 필수 수업, 예상 시간, 선수 관계, 날짜별 가능 시간,
      완료 상태, 취약 개념, 학습 선호, 학생 요청

처리: 목표일 달성 가능 여부 확인, 수업 항목 우선순위 결정,
      수업량 조절, 항목 이동, 보강 삽입, 복구 계획 생성

출력: 조정된 오늘 수업, 이후 수업 배치, 연기·통합 항목,
      목표일 영향, 조율 이유, 학생 확인이 필요한 제안안
```

LLM은 다음 역할에 제한합니다.

```text
학생 자연어 요청을 구조화된 조건으로 해석
조율 결과를 부드럽고 명확한 대화로 설명
학생 피드백을 다음 조율 조건으로 해석
```

## 현재 데모 범위

현재 단계는 전체 일정 최적화 알고리즘이나 실제 LLM을 구현하는 단계가 아닙니다.
데모에서는 사전 정의된 커리큘럼과 mock AI 응답을 사용해 아래 경험을 보여줍니다.

```text
학생이 채팅으로 시간 부족, 복습 희망, 새 진도 축소, 특정 개념 보강을 말한다.
AI 담임이 내부 조율이 이루어진 것처럼 조정된 수업안을 말풍선과 읽기 전용 오늘의 학습 안내 카드로 먼저 제안한다.
사용자는 채팅으로 동의하거나 추가 조건을 말한다.
AI 담임은 mock 규칙과 사전 정의된 답변으로 수정 또는 확정 흐름을 보여준다.
```

초기 데모에서는 목표일, 날짜별 학습 가능 시간, 복수 일자 일정 재배치의 실제 계산을 하지 않습니다.
이 값들은 전체 커리큘럼 조율 알고리즘을 구현할 때 추가할 데이터입니다.

## 후속 구현 순서

```text
1. 요구사항 반영 카드를 사용자 화면에서 제거하고 채팅 요청으로 통합
2. mock AI가 조정된 수업안과 확인 질문을 제안하도록 구성
3. 사용자 동의 또는 추가 요청에 따라 mock 편성안을 갱신
4. 목표일과 날짜별 가능 시간을 포함한 데이터 모델 정의
5. 규칙 기반 전체 커리큘럼 조율 알고리즘 구현
6. 필요 시 LLM을 요청 해석과 응답 생성 계층에 연결
```
