# 백엔드 개발 세션 시작 프롬프트

아래 내용을 새 백엔드 개발 세션의 첫 메시지로 사용합니다.

```text
AI 담임 서비스의 백엔드 개발을 맡아줘.

작업을 시작하기 전에 반드시 다음 문서를 읽고, 현재 구조와 지침을 요약해줘.
- README.md
- AGENTS.md
- docs/backend-development-brief.md
- docs/backend-api-foundation.md
- docs/domain-model.md
- docs/orchestration-rules.md
- docs/curriculum-adjustment-design.md

프로젝트 맥락:
- 이 서비스의 핵심은 사전 정의된 커리큘럼을 바탕으로 오늘 수업을 편성하고, 학생의 요구사항과 강의별 학습 결과에 따라 다음 수업을 조율하는 경험이다.
- 현재 프론트엔드는 React 기반의 채팅형 데모이며, 백엔드는 apps/api의 Fastify mock API 서버로 분리되어 있다.
- 현재 API에는 health, today-session, curriculum-map, 대화 메시지, 강의별 이해도·집중도 기록 엔드포인트가 있다.
- 실제 데이터베이스, 인증, LLM은 아직 연결하지 않았다.

백엔드의 책임:
- 요청 검증과 API 계약 유지
- 커리큘럼·학생 상태·오늘 수업·학습 기록·조율 제안의 서버 측 관리
- 규칙 기반 진도 엔진 실행
- LLM 도구 호출 오케스트레이션
- LLM이 만든 문장이 아닌, 검증된 진도 조율 결과를 우선하는 구조 유지

중요 원칙:
- 오늘 수업 편성, 보강 삽입, 진도 압축·완화, 다음 수업 조율은 규칙 기반 엔진이 판단한다.
- LLM은 학생의 자연어 요구를 해석하고, 서버 도구를 호출하며, 결과를 부드럽게 설명하는 역할만 맡는다.
- 사용자의 동의가 필요한 커리큘럼 변경은 제안안으로 먼저 반환한다. 즉시 확정하지 않는다.
- 프론트엔드는 상대 경로 /api만 호출한다. 실제 도메인, 포트, 외부 API 주소, API 키, 토큰은 docs/secrets/에만 기록하며 Git에 추가하지 않는다.
- 학생 메시지와 개인 학습 데이터, 비밀값을 로그에 남기지 않는다.
- 로그인, 결제, 관리자, RAG, 벡터 DB, 실제 영상 스트리밍은 지금 구현하지 않는다.

코드 규칙:
- 사용자에게 보이는 문구, 주석, 문서, 커밋 메시지는 한국어로 작성한다.
- 함수명·변수명·파일명·타입명은 일반적인 영어 개발 관례를 따른다.
- Fastify 앱 생성과 서버 실행을 분리한다.
- 라우트 핸들러는 검증·도메인 서비스 호출·응답 변환에 집중하고, 진도 조율 규칙은 별도 도메인 모듈로 분리한다.
- API 계약이나 데이터 모델을 변경하면 관련 docs 문서와 웹 앱의 API 클라이언트 영향을 함께 확인한다.
- 변경 후에는 가능한 범위의 타입 검사와 API 계약 검증을 수행한다.

현재 우선순위:
1. mock API 계약을 테스트로 고정하고, 성공·오류 응답을 문서화한다.
2. 프론트엔드가 오늘 수업, 커리큘럼 맵, 채팅, 강의별 체크를 API로 전환할 수 있도록 응답 타입과 경계를 정리한다.
3. 그 다음에만 기존 규칙 기반 진도 엔진을 백엔드 도메인 모듈로 옮긴다.
4. DB와 인증은 데이터 모델과 사용 시나리오가 충분히 정리된 뒤 도입한다.
5. LLM은 마지막에 서버 내부 도구 호출 방식으로 연결한다.

이번 세션에서 먼저 해야 할 일을 코드베이스 기준으로 점검하고, 필요한 작업을 구현해줘. 구현 범위가 프론트엔드 변경까지 필요하면 API 계약과 영향 범위를 먼저 설명한 뒤 최소 범위로 진행해줘.
```

## 사용 방법

새 세션을 만든 뒤 위 코드 블록 전체를 첫 메시지로 붙여 넣습니다. 세션이 특정 작업을 이어받아야 한다면 마지막 문장 아래에 현재 브랜치, 미커밋 변경, 해결하려는 백엔드 작업을 덧붙입니다.
