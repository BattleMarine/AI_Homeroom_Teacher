# 진도 조율 규칙

## 목적

이 문서는 `Adaptive Progress Orchestrator`, 즉 AI 적응형 진도 운영 엔진의 초기 규칙을 정의합니다.
초기 데모에서는 LLM이 진도 판단을 독점하지 않고, 규칙 기반 로직이 오늘 수업과 다음 수업을 조율합니다.

LLM 또는 mock AI는 다음 역할에 집중합니다.

```text
학생 요구사항 자연어 해석
AI 담임 코멘트 생성
조율 이유 설명 문장 생성
```

규칙 기반 엔진은 다음 판단을 담당합니다.

```text
오늘 수업 생성
수업량 조절
보강 삽입
진도 연기
복구 계획 생성
다음 수업 조율
커리큘럼 상태 업데이트
```

## 입력 데이터

진도 조율 엔진은 다음 데이터를 입력으로 받습니다.

```text
선택된 커리큘럼
현재 커리큘럼 단계
학생 상태
취약 개념
오늘 가능한 시간
학생 요구사항 해석 결과
강의별 간단 체크 결과
기존 다음 수업 계획
```

## 출력 데이터

진도 조율 엔진은 다음 데이터를 출력합니다.

```text
오늘 수업
조정된 오늘 수업
다음 수업 조율 결과
추가된 보강 목록
연기된 수업 목록
커리큘럼 상태 변경
조율 이유 코드
AI 담임 코멘트 생성을 위한 근거
```

## 기본 원칙

```text
필수 보강은 새 진도보다 앞에 둔다.
학생 시간이 부족하면 필수 항목을 먼저 남긴다.
이해도가 낮으면 다음 진도를 무리하게 밀지 않는다.
집중도가 낮으면 수업량을 줄이고 확인 가능한 단위로 쪼갠다.
초기 데모에서는 확인 문제 정답률을 별도 설문으로 받지 않는다.
이해도가 낮은 강의의 개념 태그를 취약 개념 후보로 표시한다.
미완료 항목은 사라지지 않고 다음 수업 또는 복구 계획으로 이동한다.
```

## 수업 항목 우선순위

수업 항목은 다음 우선순위를 가집니다.

| 우선순위 | 항목 | 설명 |
| --- | --- | --- |
| 1 | 필수 보강 | 취약 개념을 바로 다루는 짧은 보강 |
| 2 | 확인 문제 | 오늘 이해도를 확인하는 짧은 문제 |
| 3 | 현재 단계 핵심 강의 | 현재 커리큘럼 단계의 필수 개념 |
| 4 | 연습 문제 | 개념 적용을 위한 문제 |
| 5 | 다음 단계 예고 | 시간이 남을 때만 진행하는 선행 항목 |

시간이 부족할 때는 우선순위가 낮은 항목부터 줄입니다.

## 오늘 수업 생성 규칙

### 규칙 T1. 현재 단계 기반 생성

조건:

```text
선택된 커리큘럼과 currentStepId가 있다.
```

동작:

```text
현재 단계의 기본 수업 항목을 오늘 수업에 포함한다.
오늘 목표는 현재 단계의 핵심 개념을 기준으로 만든다.
```

예시:

```text
현재 단계: 로그함수 그래프
오늘 목표: 로그함수 그래프의 점근선과 평행이동 정리
```

### 규칙 T2. 취약 개념 보강 우선 배치

조건:

```text
weakConcepts에 현재 단계와 관련된 개념이 있다.
```

동작:

```text
관련 보강 항목을 오늘 수업 앞에 추가한다.
AI 담임 코멘트 근거에 "취약 개념 보강"을 추가한다.
```

예시:

```text
취약 개념: 평행이동
추가 항목: 평행이동 보강 8분
```

### 규칙 T3. 기본 예상 시간 제한

조건:

```text
오늘 수업 예상 시간이 45분을 초과한다.
```

동작:

```text
선택 항목을 다음 수업 후보로 이동한다.
오늘 수업은 35분에서 45분 사이를 목표로 압축한다.
```

초기 데모 기준:

```text
권장 오늘 수업 시간: 30분에서 45분
짧은 조정 수업 시간: 15분에서 25분
```

## 학생 요구사항 반영 규칙

학생 요구사항은 먼저 `StudentRequest` 형태로 해석된 뒤 규칙에 전달됩니다.
초기에는 자유 입력을 완벽히 이해하지 않아도 되며, 빠른 선택 버튼으로 주요 요구를 처리할 수 있습니다.

### 규칙 R1. 시간이 부족한 경우

조건:

```text
targetMinutes가 있고, 오늘 수업 예상 시간보다 짧다.
```

동작:

```text
필수 보강과 확인 문제를 우선 남긴다.
새 진도 강의는 줄이거나 다음 수업으로 이동한다.
조정 후 수업 시간이 targetMinutes를 크게 넘지 않도록 한다.
```

예시:

```text
요청: 오늘 시간이 20분밖에 없어요.
기존: 42분
조정: 점근선 보강 8분 + 그래프 확인 문제 2개
이동: 로그방정식 개념 강의
```

### 규칙 R2. 복습 위주 요청

조건:

```text
preferredMode가 review다.
```

동작:

```text
새 진도 항목 비중을 줄인다.
취약 개념 보강과 확인 문제 비중을 늘린다.
다음 단계 강의는 다음 수업으로 이동할 수 있다.
```

### 규칙 R3. 문제 위주 요청

조건:

```text
preferredMode가 practice다.
```

동작:

```text
개념 강의는 핵심 요약으로 줄인다.
확인 문제와 적용 문제를 우선 배치한다.
정답률이 낮을 경우 다음 수업에 보강을 예약한다.
```

### 규칙 R4. 특정 개념이 헷갈린다고 한 경우

조건:

```text
mentionedConcepts에 커리큘럼 개념 태그가 포함된다.
```

동작:

```text
해당 개념을 오늘 임시 취약 개념으로 취급한다.
관련 보강 항목을 오늘 수업 앞쪽에 배치한다.
이미 오늘 수업에 포함된 개념이면 확인 문제를 추가한다.
```

## 강의별 간단 체크 분석 규칙

초기 데모에서는 강의 종료 직후 이해도와 집중도만 수집한다.
헷갈린 개념, 확인 문제 결과, 수업 항목별 완료 여부를 설문으로 받는 규칙은 향후 확장용 설계이며 현재 화면에는 노출하지 않는다.
학생이 특정 개념의 어려움을 채팅으로 말하면 학생 요구사항 해석을 통해 별도 조율 신호로 반영한다.

### 규칙 C1. 이해도가 어려움인 경우

조건:

```text
understanding이 hard다.
```

동작:

```text
오늘 핵심 개념을 weakConcepts에 추가한다.
다음 수업 앞에 8분에서 12분 보강을 삽입한다.
새 진도 강의 시간을 줄인다.
```

### 규칙 C2. 집중도가 낮은 경우

조건:

```text
focus가 low다.
```

동작:

```text
다음 수업 예상 시간을 20분에서 30분 범위로 줄인다.
확인 가능한 짧은 항목 중심으로 구성한다.
긴 강의는 나누거나 뒤로 이동한다.
```

### 규칙 C3. 확인 문제 정답률이 낮은 경우

조건:

```text
totalCount가 1 이상이고, correctCount / totalCount가 0.6 미만이다.
```

동작:

```text
관련 개념을 weakConcepts에 추가한다.
다음 수업에 확인 문제 또는 보강을 추가한다.
다음 단계 진도 일부를 연기한다.
```

### 규칙 C4. 확인 문제 정답률이 보통인 경우

조건:

```text
정답률이 0.6 이상 0.8 미만이다.
```

동작:

```text
다음 수업 앞에 짧은 확인 문제를 추가한다.
새 진도는 진행하되 시간을 약간 줄인다.
```

### 규칙 C5. 확인 문제 정답률이 높은 경우

조건:

```text
정답률이 0.8 이상이다.
```

동작:

```text
현재 단계 이해가 안정적이라고 판단한다.
다음 단계 진도를 기본 계획대로 진행한다.
기존 weakConcepts 중 관련 개념은 완화 후보로 표시한다.
```

### 규칙 C6. 일부 완료 또는 미완료인 경우

조건:

```text
completion이 partial 또는 not_completed다.
```

동작:

```text
완료하지 못한 필수 항목을 delayedItems에 추가한다.
다음 수업 앞쪽에 복구 항목을 배치한다.
새 진도는 줄이거나 뒤로 이동한다.
```

## 내부 다음 수업 조율 규칙

다음 수업의 상세 편성과 조율 근거는 AI 담임 내부 도구에서 관리한다.
학생 화면에는 완료 강의, 이해도·집중도, 짧은 반영 안내만 담은 읽기 전용 진행 보고를 제공한다.

### 규칙 N1. 보강 삽입

조건:

```text
weakConcepts가 있거나, 이해도 어려움 또는 낮은 정답률이 감지된다.
```

동작:

```text
다음 수업 첫 항목으로 보강을 추가한다.
보강 시간은 기본 8분으로 시작한다.
취약 개념이 2개 이상이면 최대 12분까지 늘릴 수 있다.
```

### 규칙 N2. 새 진도 축소

조건:

```text
보강이 추가되어 다음 수업 예상 시간이 45분을 초과한다.
```

동작:

```text
새 진도 강의 시간을 줄인다.
선택 문제를 다음 수업 이후로 이동한다.
오늘 미완료 항목이 있으면 새 진도보다 복구를 우선한다.
```

### 규칙 N3. 진도 연기

조건:

```text
이해도 어려움과 정답률 낮음이 동시에 발생한다.
또는 미완료 필수 항목이 있다.
```

동작:

```text
다음 단계 진도를 일부 연기한다.
delayedStepIds 또는 delayedItems에 기록한다.
AI 담임 코멘트에는 복구 가능성을 함께 설명한다.
```

### 규칙 N4. 그대로 진행

조건:

```text
completion이 completed이고,
understanding이 easy 또는 normal이고,
focus가 high 또는 normal이고,
정답률이 0.8 이상이다.
```

동작:

```text
다음 수업을 기본 계획대로 진행한다.
AI 담임 코멘트에는 안정적으로 다음 단계로 넘어간다고 설명한다.
```

## 상태 업데이트 규칙

### 완료 상태

```text
completion이 completed이면 현재 단계 완료 후보로 표시한다.
정답률이 0.8 이상이고 이해도가 hard가 아니면 completedStepIds에 추가한다.
```

### 취약 개념

```text
헷갈린 개념은 weakConcepts에 추가한다.
정답률이 낮은 문제의 관련 개념도 weakConcepts에 추가한다.
다음 체크에서 정답률이 높으면 해당 개념은 완화 후보가 된다.
```

### 연기 항목

```text
미완료 필수 항목은 delayedItems에 추가한다.
단순 선택 문제는 delayedItems에 넣지 않고 생략 가능하다.
새 진도 강의가 뒤로 밀리면 delayedStepIds에 기록한다.
```

## 조율 이유 코드

구현에서는 자연어 문장보다 먼저 이유 코드를 생성합니다.
AI 담임 코멘트는 이유 코드를 바탕으로 생성합니다.

| 코드 | 의미 |
| --- | --- |
| `weak_concept_review` | 취약 개념 보강 필요 |
| `limited_time` | 오늘 시간이 부족함 |
| `review_preferred` | 학생이 복습 위주를 원함 |
| `practice_preferred` | 학생이 문제 풀이를 원함 |
| `low_understanding` | 이해도가 낮음 |
| `low_focus` | 집중도가 낮음 |
| `low_quiz_score` | 확인 문제 정답률이 낮음 |
| `partial_completion` | 일부만 완료함 |
| `not_completed` | 수업을 완료하지 못함 |
| `ready_for_next_step` | 다음 단계 진행 가능 |

## AI 담임 코멘트 생성 기준

AI 담임 코멘트는 다음 순서로 구성합니다.

```text
1. 현재 상태 요약
2. 조율 결정
3. 조율 이유
4. 다음 행동 안내
5. 정서적 완충 문장
```

예시:

```text
오늘 확인 문제에서 평행이동 실수가 반복되었습니다.
내일 수업 앞에 8분 보강을 추가하고, 로그방정식 강의는 25분으로 줄이겠습니다.
진도는 조금 늦어졌지만 아직 복구 가능한 범위입니다.
```

## 우선순위 충돌 처리

여러 규칙이 동시에 적용될 때는 다음 순서로 처리합니다.

```text
1. 미완료 필수 항목 복구
2. 취약 개념 보강
3. 학생이 말한 시간 제한
4. 집중도에 따른 수업량 축소
5. 다음 단계 새 진도
6. 선택 문제 또는 추가 연습
```

예시:

```text
학생이 20분만 가능하다고 했고, 평행이동도 헷갈린다고 한 경우
→ 평행이동 보강과 확인 문제를 남기고 새 진도는 다음 수업으로 이동한다.
```

## 초기 데모에서 다루지 않는 규칙

초기 데모에서는 다음 판단을 만들지 않습니다.

```text
성적 예측
정교한 진단 테스트 기반 레벨링
문제 자동 생성
장기 학습 플랜 자동 생성
학부모 리포트 생성
여러 과목 동시 최적화
실제 영상 시청 데이터 분석
```

## 규칙 테스트 예시

### 예시 1. 시간이 부족한 학생

입력:

```text
오늘 수업: 42분
요청: 오늘 시간이 20분밖에 없어요.
취약 개념: 평행이동
```

출력:

```text
조정 후 오늘 수업: 평행이동 보강 8분 + 그래프 확인 문제 2개
이동 항목: 로그방정식 개념 강의
이유 코드: limited_time, weak_concept_review
```

### 예시 2. 학습 후 체크가 낮은 학생

입력:

```text
완료 여부: 완료
이해도: 어려움
집중도: 낮음
헷갈린 개념: 점근선, 평행이동
확인 문제: 3문항 중 1문항 정답
```

출력:

```text
다음 수업 앞에 점근선/평행이동 보강 추가
```
