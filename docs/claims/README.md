# 로컬 협업 기록

제품 요구사항은 README, 작업 지침은 AGENTS를 따른다. claims는 개별 문제의 재현·인수·응답 기록이며 새 요구사항이나 별도 로드맵을 쌓는 곳이 아니다. 이 README만 Git에 추적한다.

## 기록 방법

- 재현 입력·기준 커밋·기대 결과·실제 결과·검증 범위를 적는다.
- 실패·미실행·mock·환경 차단을 구분한다. HTTP 성공만으로 DB 변경 성공을 단정하지 않는다.
- 기존 기록을 지우지 않고 같은 문서에 원인·조치·재확인 결과를 덧붙인다.
- 계약 변경은 코드와 활성 기준 문서에도 반영한다.
- 해결됐거나 다른 브랜치의 오래된 기록은 연결된 증거와 함께 archive로 이동한다.

## 파트 간 이관

여러 파트에 걸치거나 담당이 모호하면 통합 작업 세션에 모아 전달한다.

```text
통합 작업 세션에 이관
- 요청·이유:
- 완료한 부분·남은 작업:
- 관련 파일·계약·재현 근거:
- 수정 범위·의존성·미결 정책:
- 완료 기준:
- 상태: 이관 요청 → 인수 → 검증 완료
- 실제 전달 여부:
```

태그와 문서 작성만으로 전달됐다고 간주하지 않는다. 직접 전달할 수 없으면 사용자에게 알린다. 재검증 전에는 해결 완료로 표시하지 않는다.

실제 주소·포트·비밀값·개인정보는 기록하지 않는다. 요청은 상대 API 경로와 비식별 fixture로 표현하고 로그는 필요한 근거만 남긴다.
